# 3.2.4 升级校验文件修复

日期：2026-11-05。

## 原因

Windows 打包脚本使用 `Path.write_text` 写入 SHA-256 文件，未固定换行方式，导致末尾的 LF 被转换成 CRLF。已安装程序的 `parse_checksum` 只接受单行 ASCII 与 LF，读取 CRLF 时返回 `PACKAGE`，界面显示「升级文件长度或摘要不匹配」。

以 `StockAI-3.2.4-Setup.exe.sha256` 为例，原文件为 91 字节，末尾为 `0d 0a`；规范格式应为 90 字节，以 `0a` 结束。原来的发布验证按文本读取并自动归一化换行，未发现这一格式差异。

## 修复

- 安装包、Public ZIP、Hub ZIP 三个打包脚本均显式指定 LF。
- 对现有 3.2.4 的三个校验文件改用规范 LF，并保持摘要值与发行包名称不变。
- 安装包和两个 ZIP 的内容、版本与摘要不需要改变，旧版升级器即可读取修正后的文件。

## 验证

新增三项回归，直接执行各打包脚本的校验文件输出语句，在模拟 Windows 默认换行的文件写入环境下，将实际字节交给现有升级器解析。修复前全部复现 `PACKAGE`，修复后全部通过；相关校验与下载回归共 59 项通过。

已通过真实升级下载路径从 GitHub 重新读取三份校验文件，分别为 90、91、88 字节，均为 LF。当前与 3.2.2 原版解析函数全部接受；在独立临时工作区设置当前版本为 3.2.2 后，检查得到 3.2.4，并成功准备 `planned` 安装计划，摘要与 149357424 字节的已发布安装包一致。验证没有执行安装程序，也没有访问正式个人工作区。

后续发布必须按原始字节验证校验文件，不能只比较 `read_text()` 归一化后的内容。
