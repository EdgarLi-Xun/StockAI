# 打包说明

当前版本写在 `backend/cloud/__init__.py` 的 `VERSION`。正式发行打三种包，都输出到 `dist/`：

| 产物 | 用途 |
| --- | --- |
| `StockAI-<版本>-Setup.exe` | Windows 10/11 x64 每用户安装包，附 `.exe.sha256` 与 `.exe.build.json` |
| `StockAI-<版本>-Public.zip` | 独立 Web 部署包，附 `.zip.sha256` 与包内逐文件清单 |
| `StockAI-<版本>-Hub.zip` | 独立同步 Hub，附 `.zip.sha256` 与包内逐文件清单 |

安装包、公网包、Hub 包都不包含本机数据库、报告归档、`.env`、API Key、主密钥、虚拟环境或 `.tmp`。校验文件使用 LF。版本号带 `-`（如 `3.2.0-preview.3`）时，公网包清单里的阶段记为 `preview`，否则记为 `release`。

原源码本地版 `StockAI-2.0.0-Windows.zip` 仍由 `scripts/package.ps1` 生成，不在本次三种发行包之内。

## 1. 准备构建环境

在仓库根目录、Windows x64 上操作。

1. 使用项目虚拟环境 `.venv`。桌面安装包需要：

   ```powershell
   .\.venv\Scripts\python.exe -m pip install -r requirements-exe.txt
   ```

   只打公网包或 Hub 包时，安装包专用的 PyInstaller、PySide6 可以不装。公网包与 Hub 包脚本本身只用标准库读取源码。

2. 安装 Node.js，并在 `frontend` 安装依赖：

   ```powershell
   npm --prefix frontend ci
   ```

3. 安装 [Inno Setup 6](https://jrsoftware.org/isinfo.php)。编译器 `ISCC.exe` 放在默认目录，或把完整路径写入环境变量 `INNO_SETUP_COMPILER`。只打公网包或 Hub 包时不需要。

4. 把已经核对过的 Windows 版 age 1.3.2 放到：

   ```text
   .tmp\tools\age\age.exe
   .tmp\tools\age\age-keygen.exe
   ```

   官方压缩包为 `age-v1.3.2-windows-amd64.zip`（[age v1.3.2](https://github.com/FiloSottile/age/releases/tag/v1.3.2)）。Linux 部署用的固定摘要在 `deploy/cloud/install_age.py`，不能拿来代替这两个 Windows 文件。未核对前不要打安装包。`.tmp` 不会进发行包，但这两个文件会被收进安装包的 `tools` 目录。

## 2. 确认版本

发布前改 `backend/cloud/__init__.py` 的 `VERSION`，并同步更新记录。三个打包脚本都读这个值，不要在命令行另传版本号。

构建期间不要再改 `backend/`、`desktop/` 和 `frontend/dist-public/version.json`。安装包脚本会在 PyInstaller 结束后比对摘要，中途有变化会直接失败。

## 3. 建议先跑测试

打包脚本不跑测试。发布前在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest
node --test tests/frontend-*.test.mjs
```

## 4. 检查打包环境

只检查虚拟环境、Node、前端依赖、Inno Setup、age 和 PyInstaller，不开始构建：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-release.ps1 -CheckOnly
```

只检查其中一种包时加上 `-Target exe`、`-Target public` 或 `-Target hub`。

## 5. 打包

三种包一起打：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-release.ps1
```

脚本会先执行 `npm --prefix frontend run build:public`，再调用：

- `scripts/package-exe.py --skip-build`：PyInstaller 目录包，经 `scripts/bundle_slim.py` 去掉未使用的 Qt 资源后，由 Inno Setup 生成安装包
- `scripts/package-cloud.py`：公网 ZIP
- `scripts/package-hub.py`：Hub ZIP

前端已经构建过时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-release.ps1 -SkipBuild
```

只打一种：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-release.ps1 -Target exe
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-release.ps1 -Target public
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package-release.ps1 -Target hub
```

`exe` 与 `public` 都依赖 `frontend/dist-public/index.html`。`hub` 不构建前端。

安装包构建日志在 `.tmp/exe-build.log`，中间目录在 `.tmp/exe-build`。这两处可以在确认 `dist/` 产物后再删，不要删 `.tmp/tools/age`。

## 6. 核对产物

脚本结束时会重算每个产物的 SHA-256，并与旁边的校验文件比较。不一致会失败。

手工核对示例（把版本换成实际版本）：

```powershell
Get-FileHash -Algorithm SHA256 .\dist\StockAI-3.2.13-Setup.exe
Get-Content .\dist\StockAI-3.2.13-Setup.exe.sha256
Get-FileHash -Algorithm SHA256 .\dist\StockAI-3.2.13-Public.zip
Get-Content .\dist\StockAI-3.2.13-Public.zip.sha256
Get-FileHash -Algorithm SHA256 .\dist\StockAI-3.2.13-Hub.zip
Get-Content .\dist\StockAI-3.2.13-Hub.zip.sha256
```

发布时上传对应的包和 `.sha256`。安装包额外上传 `.exe.build.json`。已安装程序的升级只接受单行 ASCII、LF 结尾的校验文件。

## 常见失败

| 提示 | 处理 |
| --- | --- |
| 缺少 `.venv` 或 PyInstaller / PySide6 | 按第 1 步安装 `requirements-exe.txt` |
| 缺少 `npm.cmd` 或 `frontend\node_modules` | 安装 Node.js，再执行 `npm --prefix frontend ci` |
| 缺少 `ISCC.exe` | 安装 Inno Setup 6，或设置 `INNO_SETUP_COMPILER` |
| 缺少 `.tmp\tools\age\age.exe` | 放入已核对的 Windows 版 age，再打包 |
| 缺少 `frontend\dist-public\index.html` | 去掉 `-SkipBuild`，或先执行 `npm --prefix frontend run build:public` |
| 构建期间源码或静态资源发生变化 | 停止并行修改，重新执行打包 |
| 目录构建失败 | 查看 `.tmp/exe-build.log` |
