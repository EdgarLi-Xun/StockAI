# 研究工作台与项目助手

本轮功能同时提供 Windows 单文件 EXE 与独立公网 Web 入口。Windows EXE 打开桌面窗口，并附带共用后台和数据的本机 Web，具体见 [桌面说明](Windows-EXE使用说明.md)。独立公网开发预览为 `http://127.0.0.1:8766`；原源码本地版保留独立数据，不自动迁入新工作区。此桌面交付依据 2026-11-02 用户补充的「一个 EXE 桌面版，附属 Web」要求。

## 开始使用

登录后，点击顶部「研究增强」或侧栏的新入口。没有资料时显示真实空状态；加入自选不会自动把未核验证券当作合格候选。

1. **数据就绪度**：查看候选、严格回测、行情观察各自能否使用。问题记录附证券、原因码、报价/采集/核验时间、来源与处理入口。普通用户可定位资料，共享资料维护仍需要管理员。当前刷新读取已保存资料，不触发外部采集；旧报告保持生成时的快照。
2. **模型用量**：查看上海时间的日/月已发送次数、预留、不确定结果、已知 Token 小计和未知 usage 条数。上限留空表示未设置，零表示暂停。报告、项目对话、连接测试和重试共用上限；已发出的失败请求也占一次。界面不推算服务商订阅余额或确定账单。
3. **条件提醒**：先将证券加入自选，再设价格、相对参考收盘的涨跌幅、风险变化或指定报告候选失效。涨跌幅使用有正负号的阈值，例如“≤ -5%”；编辑阈值或暂停/启用时保留创建时已核验的参考收盘与时间，预览也使用这份参考。默认冷却 60 分钟、有效期 30 天，可指定上海时间到期、延长 30 天或持续有效，并设跨午夜免打扰。到期规则单独显示，更新有效期后才恢复评估。持续满足不重复触发；未知采样保留前次有效状态。邮件须同时满足规则开启、本人开启和站点 SMTP 配置。发送结果不明不会自动重发。移除自选会停用关联提醒，并保留触发历史。
4. **研究日志**：从证券或报告记录依据、反方观点、失效条件和私人备注。修订追加新版本；归档/恢复和删除由本人操作。第 1/5/20 个交易日观察使用“判断时点之后第一次已核验开盘”作为起点，基准日为第 1 日。目标日缺价、停牌、日历未知或公司行动不明时分别标注，不跳到其他日期。观察收益与关联模拟成交的含费 FIFO 净收益分开显示；备注不会自动进入模型输入。
5. **组合风险**：选择本人模拟账户，按有效持仓市值与现金计算同币种权益、仓位和现金占比。冻结现金是现金的一部分；待买委托不是持仓。未知行业和未穿透 ETF 保留在分母中。估值按修订次序追加，变化后恢复旧值也保留新的修订；曲线在缺口处断开，并分别展示有效估值段的回撤。只有一个有效点的段不计算回撤；局部段不能代表缺口两侧的完整区间。
6. **历史实验**：创建稳定的研究课题，保存每次独立参数与样本划分。排队取消不计尝试；实际开始后的成功、失败和中断均保留。可选择 2–5 次实验比较，重新运行产生新尝试。买入持有沿用同一预算、费用、手数和历史可成交规则，并保留未投入现金。指数只作标明口径的价格观察基准；共同起点归一化为 100，样本内外各自重置资金。冻结快照可复算，缺证据时仍标为未验证。
7. **AI 助手**：可以聊天，直接让助手查询“最近的报告”“我的回测结果”或某只证券，无需附带分析结果。也可从资料页面进入或在“指定研究资料（可选）”中指定对象。明确询问最近两份报告时自动查找并比较；多个对象无法确定时先澄清。资金汇总和逐笔成交授权互相独立，收窄权限后不再外发受限历史。

## 助手的回答与状态

助手支持普通聊天、项目帮助和按需查询已保存的研究结果。配置与添加股票只生成待应用方案；删除及已有业务数据的修改必须由本人在相应页面手动操作。助手没有文件、命令、交易、删除或任意网络工具，不能操作项目外内容。项目帮助来自版本化的已实现功能清单。

例如输入“把单只证券预算调整为五百元”，助手会展示当前值与拟修改值，点击“应用配置”后才保存。可调整个人预算、最低日成交额、风险核验期限、费用数值和研究计划；不通过助手修改凭据、站点路径、账号或任意文件。方案生成后配置发生变化时，旧方案不能覆盖新配置，需重新生成。

输入“添加贵州茅台到自选”后，核对助手查到的市场、代码和分组，再点击“添加到自选”。未知代码时先查询或澄清。已有自选不会被重复添加，也不会覆盖原有分组或置顶；添加证券不代表行情、身份或交易资格已核验。

发送问题时会附带当前问题、必要的近期完整对话及按需查询的已授权事实。单条限制 4,000 个 Unicode 码点；最多同时读取 5 项资料、比较 2 份报告，并保留近期 10 轮完整对话。每条消息最多进行 3 轮查询，再生成回答；每次实际模型调用分别计入个人日/月上限，安全临时错误最多重试一次，不确定发送不重试。查询只读本人资料和共享证券，不把全部历史结果一次装入请求；大型报告可按证券筛选。输入仍遵守 8,000 Token 的保守字节上界或配置中更小的窗口。

回答和方案先经过结构、范围、配置白名单及引用校验，再完整显示。普通聊天无需研究引用；研究数值由程序事实卡呈现，不补造未经核对的事实或交易建议。来源卡可打开原报告、帮助、个人配置或对应资料，显示版本与数据时间；自动查询的追问重新读取原来源，来源删除后不再发送其历史。旧报告保持原快照，不用当前行情补写历史。

每个会话同时只处理一个未结束回答。断线、刷新或回到会话会读取原请求状态；不会自动再次调用模型。停止先确认请求状态，并尽力关闭供应商连接；供应商是否停止计费不能由本地保证。不确定发送不自动重试；点击「重新生成」创建新请求，可能再次占用额度。无可用配置时可查看明确标注的项目帮助资料；服务调用失败显示原因。

## 草稿与数据维护

表单可「保留草稿收起」，离开时选择保留或放弃。未保存草稿仅保留在本次登录内，刷新、退出或会话失效会清除。日志、提醒等采用乐观版本控制；并发保存遇冲突会保留草稿，需重载后再编辑。列表按 20 / 50 条分页，旧会话消息和日志修订按需读取。

新增私人对象按用户隔离，管理员也不能通过本人接口读取他人正文。删除会话、提醒和日志会先持久化独立删除意图，防止旧备份恢复后复活。

## 部署与恢复补充

沿用 [公网部署说明](../deploy/cloud/README.md)。当前开发交付版本为 `3.1.0-preview.1`。部署包新增 `config/assistant-knowledge.json`；Dockerfile 与打包脚本已包含此文件。数据库升级为增量建表，`cloud_meta.research_schema_version=2`，既有报告和账本不改写。原研究 schema 1 的观察与估值逐字复制到新历史表，保留旧表；复制与版本标记在同一事务中提交，失败一起回滚。新序号仅排列实际存在的旧估值，不补造丢失的历史。

`STOCKAI_ERASURE_DIR` 新增 `research-authority.sqlite3` 和 `research-head.json`，保存带签名的最新资源删除与调用计数。它们与既有注销权威记录一样，必须作为最新控制状态独立保护；不能用旧业务备份替换。业务 age 备份不会包含这两份可回退的旧副本。恢复前核对最新控制状态，再应用资源删除；会话、旧凭据、自动 AI 及未完成任务需要重新确认。控制状态缺失、损坏或回退时拒绝恢复/启动，不可删除标记来绕过核对。

上线前保存完整控制目录与主密钥的受控备份。若升级失败需回退，使用升级前的业务及控制状态完整检查点；不要让旧程序在新控制状态未核对时继续发送 AI 或提醒。真实模型、SMTP、域名与生产 Linux 主机需按 [本轮验收记录](验收记录-研究工作台与AI助手.md) 单独联调。
