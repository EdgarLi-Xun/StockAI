# 同步、独立部署与升级

3.2.0-preview.2 修复项目助手问候、选定资料分析和连续追问误拦截，见 [修复记录](修复记录-助手对话误拦截.md)。旧错误消息作为历史保留，发送新消息即可使用修复逻辑。

适用版本：3.2.0-preview.1。桌面仍为单个 Windows EXE，附属本机 Web 共用同一工作区。新增两份 PRD 的目标服务实机验收另见《验收记录-同步与升级》，不要把受控测试视为所有 NAS、域名和多机环境均已通过。

## 选择运行方式

| 方式 | 启动 | 数据与后台 |
|---|---|---|
| 本机桌面 | 双击 `StockAI-3.2.0-preview.1-Windows.exe` | 默认 `%LOCALAPPDATA%\StockAI\workspace`，与本机 Web 共用服务；菜单可打开 Web |
| 指定本机工作区 | `StockAI.exe --local --data-dir D:\StockAIWorkspace` | 沿用该目录的资料、独立控制记录与密钥，不能只复制数据库 |
| 远程桌面客户端 | 桌面菜单“连接远程 Web…”；或 `StockAI.exe --remote-url https://research.example.com --remote-account me@example.com` | 只运行 HTTPS 客户端，不启动本机研究后台；按站点和账号名称隔离缓存 |
| 独立 Web | `deploy/cloud/compose.yml` | 无 Qt 依赖；资料、凭据、控制目录分卷，浏览器关闭不停止服务 |
| 独立 Hub | `deploy/hub/compose.yml` | 独立账号、空间、设备授权、密文存储及条件写入，不采集行情或调用模型 |

本机桌面关闭窗口后驻留托盘；“退出 StockAI”停止本机服务。远程客户端退出不会停止远程 Web 或 Hub。远程客户端菜单中的“关于与升级本机客户端…”仅更新本机客户端；网页内的站点升级仍归远程管理员管理。

本机研究工作区包含 `data`、`control`、`secrets`。远程客户端更新使用独立的 `client-state`，不打开本机研究库。不要删除 `control` 或 `secrets` 来处理同步故障，也不要同时让旧、新程序写同一工作区。

同步绑定与本地记录标识另有加密恢复材料，保存在 `control/sync-private`，控制日志只保存其摘要引用。恢复旧业务备份时会先恢复最新绑定、唯一待发版本和标识，再核对删除状态。账号注销且当前/历史后端清理均完成后，才删除这些私有材料。

## 连接个人同步空间

1. 登录后打开顶部“同步与版本”→“个人资料同步”。选择 Hub 或 WebDAV，填写 HTTPS 地址与设备名。
2. 新建空间需本人在目标服务的账号；已有空间需从已授权设备导出的恢复材料。Hub 加入还需同一 Hub 账号和十分钟、单次设备授权码。
3. 验证后查看本机待发数、远端资料数与删除标记数。确认该次预览后才合并。首次合并先创建本人加密恢复点。
4. 核对结果后可开启自动同步。本机改动约五秒合并，远端约六十秒轮询；断网、认证失败或空间不足时保留本地资料和待发密文。

同邮箱不等于同一同步身份。不会根据邮箱合并独立站点账号。一次仅绑定一个同步后端；同步的是加密业务对象和版本关系，禁止把正在运行的 SQLite、WAL 或研究文件夹放进网盘进行整库覆盖。

Hub 按空间提供有界游标分页，成功接收和持久化后确认进度；确认响应丢失可重复恢复。页面显示尚有批次时需继续同步，不把已经传完本机待发队列误报为远端资料全部接收完成。

同步范围包括自选、偏好、模型描述、报告及原始附件、研究对象与修订、观察/估值历史、完整模拟账本、实验/回测快照、对话状态、提醒和投递历史。模型 Key、密码、会话 Cookie、SMTP/WebDAV 凭据、站点主密钥和模型数据授权不会进入业务包。接收的模型描述保持未连接；提醒、待成交委托、在途任务不会自动执行。

### WebDAV / NAS

连接时实际验证 MKCOL、PROPFIND、读写、强 ETag 与 If-Match。若服务忽略条件写入、缺少强 ETag 或证书不受信任，停止双向写入。探测只删除本次随机生成的临时对象。服务不提供配额属性时显示容量未知。

必须使用 HTTPS。本机可明确勾选受信任内网 NAS；Web 运行端还需运维设置 `STOCKAI_SYNC_PRIVATE_NETWORKS`（逗号分隔 CIDR）。默认不允许普通 Web 用户访问内网。证书 CA 仅从运行端的 `STOCKAI_SYNC_CA_FILE` 加载，不接受浏览器传入服务器文件路径，不跟随携带凭据的重定向。

### 恢复、冲突和删除

“设备、冲突与恢复点”可查看双方版本及共同基线。普通冲突选择本机或远端会生成新版本，保留原历史。账本与不可变归档不相互覆盖，可保留为独立分支副本。个人恢复点以新版本恢复可变记录；已有删除标记、账本和不可变归档会明确跳过。

删除标记长期保留，旧设备的离线编辑不能复活被删资料。显式恢复删除记录需指定当前墓碑并生成可追溯的新版本。不可变对象同 ID 不同内容会隔离。

“暂停”保留绑定、资料和待发队列。“解除绑定”保留本机资料和旧空间恢复材料，不删除远端。“删除我的远端同步资料”删除远端业务密文并保留防回退控制信息；离线时显示清理等待，不能视为已经删除。注销账号同样保留独立的远端清理意图。

### 账本、执行端和调用上限

每个模拟账本仅一个有效写入端与代次。其他端只读，收到的待成交委托保持停用；离线只允许继续本人原有分支。在线转移先确认完整账本和待发记录已同步。旧代次回传导致冻结，现金和成交不会相加或重放。

自动报告和提醒需要在线核验执行归属，领取稳定执行凭据；不确定结果阻止无依据的切换或重发。接收规则不会打开本端自动化开关。

有限日/月额度在模型真实发送前进行跨端条件预留，包括 Ollama、连接测试和重试。服务不可达时暂停有限额的新 AI 请求，规则研究可继续。不限额的本机调用可离线保留为未确认用量，联网后补记；页面不会将其宣称为已确认全局总数。新共享上限需所有有效设备确认后生效，离线设备未确认时明确显示等待。

### 更换后端和密钥

先完成旧端同步，处理冲突和未决执行；暂停后选择“更换同步后端”。其他设备需完成同步并撤销旧绑定，才能封存旧空间。迁移预览展示目标、资料、墓碑和上限；确认后重加密业务对象并保留全局标识、用量和代次。目标确认丢失可继续同一计划，不切回双写。其他设备使用新恢复材料重新加入。

迁移保留加密的前后版本映射证明。旧设备重新加入时据此识别原有本地记录，避免产生重复资料或把已经删除的旧记录作为新资料上传；经过多次后端更换仍沿用原标识。恢复材料包含必要的旧空间解密材料，须与当前同步密钥同等保护，不含旧服务登录密码。

导出恢复材料需再次验证当前账号密码。恢复材料包含同步解密密钥，应与登录密码分开保管。撤销设备后建议轮换密钥；轮换会使其他设备需要新的恢复材料，不能自动取得新密钥。

## 独立 Hub 部署

参照 `deploy/hub/README.md`。Hub 使用独立域名、数据卷和控制卷；账号由运维 CLI 创建，无公网自助注册。普通 Web 站点仍按 `deploy/cloud/README.md` 初始化。Web 和 Hub 可以分机部署，不要求安装桌面或 Qt。

## 关于与升级

“同步与版本”→“关于与升级”。已有预览版保留预览通道；稳定通道只选择稳定版。默认只通知，可开启自动下载，安装始终需确认。无更新源、断网、过期元数据或限流显示检查失败，不显示为“最新”。

本项目未附带生产更新域名或发布私钥。运维需安装验证后的公开发布根到 `STOCKAI_RELEASE_ROOT`，并按需配置 HTTPS `STOCKAI_RELEASE_SOURCE`。没有可信发布根时，离线清单同样不能绕过验签。EXE 的 `.sha256` 用于人工校验文件，不等于发布身份签名。

更新方案核对组件、平台、架构、安装形态、来源版本、schema/API/同步能力、工作区、包长度与摘要。清单采用 Ed25519 阈值签名，根轮换要求旧、新根双重授权，并检查时效、撤销和独立的防回放下限。这是项目自定义协议，并非完整 TUF 实现。

桌面本机版预检后显示具体版本与目标工作区，需本人确认退出和重启。受控辅助进程等待原进程及服务锁释放，验证加密恢复点，安装到不活动的版本目录，再运行新程序探针。探针核对版本、静态资源摘要、数据库/FK/记录数、归档和控制状态，不调用真实模型、撮合或发邮件。预开放写入失败恢复原代码与检查点，并重新应用最新删除和用量控制。

远程客户端的恢复点仅保存客户端配置，客户端升级探针不打开研究数据库或连接远程数据接口。它使用独立的升级控制目录。

### Web / Hub 运维执行

网页管理员可以准备、下载、导入和预检计划；没有本机执行器时显示“等待运维执行”。网页不能输入任意服务器命令。运维停止对应服务后使用：

```powershell
python -m backend.upgrades.cli status --component web
python -m backend.upgrades.cli preflight --component web --id <事务ID> --identity <离线age身份文件>
python -m backend.upgrades.cli execute --component web --id <事务ID> --confirmation <计划中的确认摘要> --identity <离线age身份文件>
```

Hub 将组件改为 `hub`；本机离线维护可使用 `--component desktop --home <工作区>`。恢复可使用 `recover`；普通更新拒绝降级。已开放新版写入后，回退先保存当前状态；无经过验证的逆向迁移时明确阻止旧检查点覆盖新记录。

服务器默认不挂载 age 私钥。执行迁移时需由运维提供可验证的离线解密身份；缺少工具、权限、磁盘或恢复材料会阻断安装。源码部署和 EXE 不能互换。容器使用固定入口选择已验证的版本目录；也可按签名计划由运维构建/切换镜像，实际目标镜像仍需部署验收。

### 离线发布工具

`scripts/release-sign.py` 提供离线根初始化、发布清单签名和跨根签名封装。`init --directory <独立离线目录>` 创建两把根私钥（阈值二）及一把发布私钥。只向运行端分发 `release-root.json`，私钥不得放进 EXE、源码包、Web、Hub 或同步目录。`release --help` 查看组件、形态、版本、单调序号及包 URL 等必填参数。

“安装缓存与恢复点”可清理已结束且超过 30 天的升级文件。本机/Web 每日检查一次；Hub 运维可使用 `python -m backend.upgrades.cli cleanup --component hub` 预览，加 `--apply` 执行。保留活动程序及可用旧代码，数据检查点按 30 天保留上限过期；页面标明过期后不能按该检查点恢复。未完成事务暂缓清理，工作区、密钥、独立控制和待同步记录不在清理范围。

单个业务聚合上限 32 MiB、加密控制清单上限 8 MiB，超限停写并给出错误，本地资料仍保留。实际 NAS、跨机器长时间离线、大历史迁移和生产签名源验收状态见独立验收记录。
