## 1. 背景与目标

1.0 版需求提出时，StockAI 是以 Windows 本机使用为主的股票研究终端，模型调用仅支持本机 Ollama，研究数据和模型设置为全站共享。当时管理员、只读者登录代表共享角色，尚无个人账号。

本次新增需求将使用场景扩展为公网多用户服务：使用者通过自己的账号登录，独立维护研究内容与模型配置，使用自己的模型凭据生成报告。首家云端模型服务接入 MiniMax 订阅 Key，同时保留 Ollama 支持。

目标：

1. 建立个人登录身份及注册、验证、找回密码流程。
2. 隔离个人模型配置和个人研究数据，共用公开市场资料。
3. 支持保存多套模型配置，并为每个用户选择自己的默认配置。
4. 提供可在单台 Linux 云服务器运行的公网服务。
5. 明确云模型接收的数据范围，以及后台任务使用个人额度的条件。

## 3. 账号与注册

### 3.1 注册和邮箱验证

- 注册需要邀请码、邮箱和密码。
- 邀请码由管理员生成，单人单次使用，自生成起 7 天内有效，管理员可撤销。
- 注册流程包含邮箱验证；验证完成后才能使用研究功能。
- 每个使用者拥有独立登录身份，能够登录、退出及切换账号。
- 提供邮件找回密码流程。
- 公网版本中的身份识别不能依赖现有“本机请求自动取得管理员身份”的行为。

邀请码的占用与核销应保证同一码不能创建多个账号；重复提交、验证重发等流程应保持一致。邮件验证及密码重置令牌的实现方式在技术设计阶段确定。停用与注销见第 3.4 节。

### 3.2 初始化管理员

- 初始化时明确指定管理员账号。
- 原有单人研究数据迁入该账号的个人研究空间。
- 管理员负责账号、邀请码、共享行情、风险核验及站点运维。
- 管理员同样拥有自己的个人研究空间；站点维护角色不赋予在后台查看他人私人报告、持仓或完整 Key 的入口。
- 管理员再次验证密码后可以导出含全站数据的加密备份，保留及恢复规则见第 9.3 节。上述后台功能边界不代表服务器运维者在技术上完全无法接触底层数据。

### 3.3 登录账号与模拟账户

登录账号代表使用 StockAI 的人；模拟账户代表虚拟资金、持仓和交易记录。两者是不同概念，现有模拟账户不能直接充当登录账号。

### 3.4 停用与自助注销

- 管理员可以停用账号，停用后撤销登录会话并停止该账号后续模型调用。
- 用户可以自助发起注销，经确认后立即清理在线个人研究数据和 Key。
- 停用或注销时应处理该用户尚未执行的任务，防止继续调用模型。
- 已经发出的请求所发送的内容和已消耗的供应商额度无法撤回；在途任务结束后不得重新写回已注销的个人空间。
- 旧备份副本最多保留 30 天，恢复时不得使已注销的账号及其个人数据重新出现，见第 9.3 节。

## 4. 数据归属与隔离

### 4.1 个人研究空间

以下内容归属于个人用户：

- 自选证券及其个人分组、置顶等研究选择。
- 研究报告、候选结果及相关个人研究记录。
- 模拟账户、模拟持仓、委托、成交及资金账本。
- 回测记录、结果及与其关联的研究快照。
- 个人研究参数，例如研究预算、模拟费用及筛选偏好。
- 模型配置、凭据、默认模型选择及个人自动 AI 调用开关。
- 与个人研究任务关联的执行状态和通知。

用户列表查询、详情查询、按 ID 访问、下载和导出均须遵守相同的数据归属边界。用户不能通过另一人的记录 ID 获取或修改其个人数据。

### 4.2 共享市场资料

公开行情、证券基础资料和可共用的市场缓存供各用户共同使用。共享资料不包含某个用户的自选关系、私人备注或研究结果。

共享证券风险核验、历史行情导入及市场资料维护由管理员管理。普通用户维护自己的个人研究空间。

### 4.3 报告与任务归属

- 同一日期、同一报告类型可以由不同用户各自生成。
- 一人的报告不能因为全站相同日期和类型的去重规则而被另一人复用。
- 模型调用、报告、候选及任务记录应能够追溯到所属用户。
- 模型失败时归档规则报告，明确显示失败或回退原因，不自动换用其他模型配置。
- Key 恢复或更换模型后，用户可主动为报告补充 AI；补充结果形成新版本，原始归档保持可追溯。
- 同一用户对同一生成任务的重复提交应复用其任务状态，避免重复调用模型；主动补充 AI 则形成独立的新版本。
- 同一用户、同一类型、同一目标日期的自动任务保持去重；去重范围包含用户归属。

## 5. 模型配置与凭据

### 5.1 个人模型配置

- 用户可以保存、管理多套模型配置。
- 配置能够区分所用模型服务、模型及相应凭据。
- 每个用户从自己的配置中选择默认配置。
- 默认选择仅影响该用户的研究任务，不改变其他用户的默认选择。
- 第一家云端服务为 MiniMax，保留 Ollama 接入能力。
- 提供通用 OpenAI 兼容配置，MiniMax 提供现成预设。

配置名称、地区、模型标识及凭据状态应足以让用户辨认正在使用的配置。新用户未设置可用模型、模型调用失败或输出无效时，生成标明原因的规则报告。

### 5.2 MiniMax 订阅 Key

- 使用用户自己的 MiniMax 订阅 Key。
- 提供国内站与国际站预设，默认选择国内站。
- 实际调用使用与所选地区匹配的接口。
- 订阅 Key 按其订阅资源使用，不能被当作普通按量付费 Key 处理。
- 模型可用性与额度、限流状态应体现在个人配置或任务状态中。
- 不把“订阅”解释为无限调用，也不承诺固定的供应商响应速度。

具体默认模型 ID、协议适配方式及额度展示能力在技术设计和联调时确定。

### 5.3 凭据隔离要求

- 凭据与配置所属用户保持一致。
- 不通过普通设置读取、列表、配置导出、日志或报告返回完整 Key。
- 用户 A 的任务不能使用用户 B 的 Key。
- 服务端保存及使用凭据时的加密、主密钥管理、轮换与恢复方案，在技术设计中明确。
- 管理员后台不提供查看其他用户完整 Key 的入口。

### 5.4 Ollama 在公网部署中的含义

现有 Ollama 调用由后端执行，回环地址代表后端所在的机器。后端部署到云服务器后，`localhost` 指向云服务器，而非访问者的电脑。

本次采用管理员在服务器部署的 Ollama 实例，用户可以选择使用该服务。连接每个使用者自己电脑上的 Ollama 另立需求。Ollama 的服务器地址属于站点配置，个人模型配置引用该服务及所选模型。

### 5.5 通用 OpenAI 兼容配置

- 用户可在自己的模型配置中填写 HTTPS API 地址、模型名与 Key。
- 通用配置适用于实现所需 OpenAI 兼容文本接口的服务，不承诺所有自称兼容的服务均无差异。
- 云端地址的访问校验与服务器本地 Ollama 的站点配置分别处理，不能通过普通用户自定义地址访问服务器内部服务。
- 超时、接口不兼容或输出验证失败时沿用规则报告回退，不能自动尝试用户未选定的其他配置。

## 6. 云模型的数据范围

### 6.1 默认发送范围

默认只发送完成研究解释所需的自选、候选及去除身份信息的研究摘要。默认不发送：

- 登录身份和账号凭据。
- 模拟账户名。
- 用户自由填写的备注。
- 逐笔成交明细。

自选及候选的组合本身也属于个人研究选择；它们是用户已同意纳入本需求默认模型输入的内容，不应被描述成纯公开数据。

### 6.2 详细数据主动开启

授权按每套模型配置分别保存，提供两个独立开关，初始均为关闭：

| 授权项 | 允许加入的内容 | 边界 |
| --- | --- | --- |
| 模拟账户汇总 | 去除身份信息的模拟资金、持仓等结构化汇总 | 不附账户名、登录身份及自由备注 |
| 逐笔成交 | 研究所需的模拟成交证券、方向、数量、价格、费用和时间 | 不附账户名、登录身份及自由备注 |

默认研究摘要不包含尚未授权的模拟账户汇总或逐笔成交。首版无论是否开启详细数据，都不将账户名、自由备注、登录身份或账号凭据放入模型提示词。

关闭授权立即作用于后续模型调用，并阻止相关尚未发出的调用；授权撤销不改写既有报告，已经发出的请求无法撤回。新建的模型配置不会继承另一套配置的详细数据授权。

原本地版代码会把完整研究事实对象交给模型，完整版包含账户、现金和逐笔成交。云端接入应显式构建获准发送的输入，不能直接沿用整个对象。

### 6.3 既有研究职责

沿用既有产品职责：程序决定行情事实、预算、候选及来源，模型生成定性解释。更换模型服务不自动扩大模型对交易规则、候选或可执行数值的决定权。

## 7. 自动任务

### 7.1 个人报告计划

- 新用户的个人定时报告默认关闭，可分别开启早报、收盘报告和周复盘。
- 新用户的自动 AI 调用默认关闭。
- 用户主动开启后，后台任务可在用户退出登录后继续运行。
- 开启定时报告而未开启自动 AI 时，只生成规则报告。
- 开启自动 AI 后，每个任务使用提交时选定的该用户默认模型配置及其凭据。
- 用户能够识别自动任务正在使用自己的订阅额度。
- 个人研究任务与共享行情采集、站点备份等站点任务应分别定义归属。

默认计划统一使用 `Asia/Shanghai`：

| 报告 | 默认计划 |
| --- | --- |
| 早报 | 每天 08:00 |
| 收盘报告 | 经交易日历核验的交易日 16:00 |
| 周复盘 | 每周日 20:00 |

停机后仅补跑当天到期任务，不补造更早日期的历史报告。补跑仍遵守当前账号状态、个人开关、凭据与授权规则。

### 7.2 排队和重试

- 每个用户最多有 1 个报告生成任务运行、1 个排队；全站最多同时运行 2 个报告生成任务。
- 排队状态应可追踪，不能在重复点击时悄悄创建额外模型调用。
- 明确可重试的临时错误最多自动重试 1 次。
- Key 失效、额度不足及请求结果不确定的超时不自动重试。
- 调用最终失败、限流未恢复或模型输出无效时，生成标明原因的规则报告，不自动切换其他配置。
- 用户可以在问题恢复后主动补充 AI，保留原档和新版本。

具体错误分类、退避时长、HTTP 超时和 Ollama 资源调度由技术方案明确，并服从以上调用次数与并发边界。

### 7.3 配置与授权变更

- 任务提交时固定所用模型配置；更换默认配置只影响新提交的任务。
- 已排队任务不能因修改默认配置而自动换用另一套凭据或服务。
- 实际发起调用前检查账号、Key 和数据授权是否仍有效；这项检查也适用于重试及补跑。
- 停用账号、删除 Key、撤销相关授权时，阻止相关尚未发出的调用；处理已发请求时遵守第 3.4 和第 6.2 节。
- 配置版本、凭据引用及任务快照的存储方式由技术设计确定，不得把已固定配置理解为允许继续使用已撤销凭据或授权。

## 8. 历史数据迁移

- 迁移前保留可恢复的原始数据副本，并遵守第 9.3 节的备份访问和保留规则。
- 现有自选关系、报告、模拟账户、持仓、回测及关联记录归初始化时指定的管理员。
- 公开行情和证券基础资料保持共享归属。
- 新注册用户从空白个人研究空间开始，不能默认看到管理员的历史研究数据。
- 迁移需覆盖数据库记录和报告文件的归属，保持关联完整。

现有配置中的个人研究参数与站点参数需要拆分；数据结构、迁移与回滚安排见实施方案，迁移脚本在开发阶段实现并验证。

## 9. 公网部署与首发验收

### 9.1 部署范围

- 单台 Linux 云服务器运行公网 Web 服务。
- 公网基线交付聚焦 Linux Web；2026-11-02 已补充 Windows 桌面独立部署和 Hub/WebDAV 同步，按第 14 节及独立 PRD 实施，不将其当作已有公网部署能力。
- 提供可复现的安装、启动、配置、备份和恢复说明。
- 公网登录、凭据录入及邮件中的站点链接应使用 HTTPS 入口。
- 注册验证与密码找回使用站点事务邮件能力。
- 公开入口、持久数据和后台任务需要具备明确的运行配置。

数据库、持久任务、会话、容器及反向代理按独立实施方案落实。现有进程内会话和全局单工作线程不能未经验证就视作已经满足目标。

### 9.2 验收用例

以下为基线计划验收条件；实际验证结果与目标环境待验事项见 [验收记录](验收记录-公网多用户与模型接入.md)，不以本表代替验证结论：

| AC-09 | 同日期同类型报告由不同用户同时发起 | 各人获得自己的报告与任务结果，不因全站去重而复用他人结果 |
| AC-10 | 单台 Linux 环境、20 个账号、2 人同时生成报告 | 请求可接受、状态可追踪并能完成；数据和凭据不串用。性能数值另行实测记录 |
| AC-11 | 模型返回无效结构、修改程序候选或引用不存在的来源 | 保持既有输出验证约束，不将无效模型解释当作有效研究内容 |
| AC-12 | Key 失效、限流、额度不足或输出验证失败 | 生成标明原因的规则报告，不自动切换其他配置 |
| AC-13 | 用户恢复 Key 后为规则报告补充 AI | 产生可追溯的新版本，保留原始归档 |
| AC-14 | 管理员使用站点后台 | 可管理账号与共享资料；没有读取他人私人研究或完整 Key 的后台入口 |
| AC-15 | 管理员停用用户 | 登录会话失效，尚未执行的任务不再调用模型 |
| AC-16 | 用户确认自助注销 | 个人研究数据与 Key 被清理，不因在途任务结束而重新出现；备份恢复另见 AC-21 |
| AC-17 | 用户选择服务器 Ollama | 后端使用管理员部署的服务器实例，个人电脑连接不纳入本次验收 |
| AC-18 | 用户添加通用 OpenAI 兼容配置 | 使用本人填写的 HTTPS 服务地址、模型和 Key；失败按既定规则报告行为处理 |
| AC-19 | 邀请码过期、撤销、重复使用，或账号尚未验证邮箱 | 不能借此重复注册或提前访问个人研究功能 |
| AC-20 | 每天备份、管理员导出、到期清理 | 备份加密；管理员再次验证密码后才能导出；系统管理的副本不超过 30 天保留期 |
| AC-21 | 从包含已注销用户的旧备份恢复 | 已注销账号及其私人研究不重新出现；无法保障时阻止恢复发布 |
| AC-22 | 开启定时报告、关闭自动 AI | 按个人计划只生成规则报告，不调用模型；停机只补跑当天任务 |
| AC-23 | 用户连续提交任务或多人同时提交 | 每人 1 个运行加 1 个排队，全站不超过 2 个运行；重复提交不额外调用 |
| AC-24 | 临时错误、无效 Key、额度不足或结果不明超时 | 可重试临时错误最多重试 1 次，其余所列错误不自动重试 |
| AC-25 | 排队后更换默认配置、删除 Key、停用账号或撤销授权 | 改默认不改动已提交任务；撤销与停用阻止相关未发调用 |
| AC-26 | 分别开启、关闭某套配置的模拟账户汇总或成交授权 | 仅发送该配置当前获准的数据；不发送账户名或自由备注；撤销不改写已有报告 |

### 9.3 站点备份、保留和恢复

- 每天自动创建加密的站点备份，保留 30 天，包含恢复所需的数据库与报告归档。
- 只有管理员再次验证密码后可以导出；备份包含全站用户数据，属于站点运维权限。
- 用户注销后立即清理在线个人数据，旧备份副本在保留期内可能仍有记录，最多保留 30 天。
- 系统自动清理其管理的到期副本；已导出的离线副本由管理员按同样期限清理。
- 恢复时核对并应用已注销状态，不能恢复已注销账号及其私人研究数据；如果不能保障这点，应阻止恢复结果对外启用。
- 注销记录、加密密钥、备份完整性校验及恢复流程的具体方案在技术设计中明确。
