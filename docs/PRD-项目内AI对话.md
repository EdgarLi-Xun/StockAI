## 1. 目标与入口

提供右下角悬浮入口和主导航中的“AI 助手”独立页面，帮助用户理解和使用 StockAI，并解释本人在项目内的研究结果。两种入口必须同时提供，支持连续多轮对话，以及从证券详情、报告、模拟交易和回测页面发起“就此提问”。

对话页显示当前模型配置、所选上下文和资料时间；用户可以查看引用资料、开始新对话、停止生成、查看历史和删除对话。切换页面不应悄悄替换正在讨论的报告或研究对象；更换上下文时应明确显示。

报告追问支持选定本人两个报告版本进行比较。程序确定候选、排除原因、预算、行情和证据状态的差异，模型解释并引用两侧快照；同事实换模型的解释变化不能描述成行情变化。缺少原始报告或证据时说明缺口，不用当前数据补写历史。

### 1.1 右下角悬浮助手

- 登录后的业务页面在视口右下角固定显示助手按钮，滚动页面时入口位置保持稳定；登录、注册和未授权页面不展示可访问的私有会话。
- 桌面视口默认距右侧、底部各 24 CSS 像素，按钮触控区域至少 44×44 像素。存在底部导航、系统安全区或其他固定操作时向上避让，不遮挡关键按钮和数据。
- 点击打开从右下角展开的对话面板，桌面默认约 400×600 像素，并限制在可用视口内。面板包含消息、输入、模型及上下文摘要、新会话、停止、收起和“在独立页面打开”等操作。
- 悬浮面板允许一边查看业务页面一边提问。收起、关闭面板或切换业务页只改变展示，不等同于停止生成、退出会话或清空草稿；停止生成使用单独按钮。
- 收起时用可读状态提示正在生成或有新回复，重新打开继续显示原会话；不能因打开、关闭或提醒动画额外调用模型。
- 业务确认弹窗和安全操作遮罩优先于助手，浮层不得覆盖确认内容或抢夺输入。支持键盘打开、关闭和返回入口焦点，按钮具备可读名称。

### 1.2 独立助手页面

- 主导航固定提供“AI 助手”入口，拥有可直接访问和刷新的独立地址；进入已有会话前检查当前用户归属。
- 独立页提供历史会话列表/检索、新建、切换、删除、完整消息区、输入区、模型配置选择及上下文/来源查看，可容纳比悬浮面板更长的阅读与对照操作。
- 从悬浮面板“在独立页面打开”时进入同一会话，从业务记录“就此提问”时带入明确的对象及版本，不自动提交问题或消耗额度。
- 独立页已经显示当前对话时，不再叠加第二份悬浮聊天面板；如果保留右下角按钮，它只用于定位当前对话，不能产生另一份会话或第二个生成任务。

### 1.3 双入口共享状态

- 两种入口共用会话 ID、消息 ID、请求标识、当前模型、所选对象及版本、未发送草稿和正在生成的任务状态；同一登录会话内切换时保留阅读位置，避免从头重看。
- 面板与页面切换仅切换展示容器，不能复制消息、重新提交、取消原任务或重复扣减调用次数。共享状态继续遵守同会话串行、断线恢复及原有幂等要求。
- 正在生成的请求保留提交时的模型和资料快照，切换入口不修改它；界面中新选模型或上下文只影响下一次明确提交的问题。
- 切换业务页面不自动替换已有对话的研究对象。可提示“使用当前页面资料”，由本人明确选择后更新上下文清单；未选资料不能因悬浮面板常驻而被读取和外发。
- 发送前始终可见当前模型和上下文摘要，必要时展开查看来源、报告版本与时间。两入口使用同一授权、范围限制、错误提示和调用上限。
- 草稿保持在当前身份隔离的客户端状态，未发送前不因切换入口上传给模型。退出登录、切换账号/站点或会话被撤销时，立即清理界面中的该身份消息、草稿和引用；迟到响应不能写入下一身份的界面。

### 1.4 移动端与桌面一致性

Web 与桌面内嵌界面采用相同双入口规则。360 CSS 像素窄屏下，右下角入口保留，面板可改为适配可用空间的全宽抽屉；独立页仍可正常访问，历史列表可折叠。

移动端预留安全区、底部导航和软键盘空间，输入及发送/停止按钮保持可达；收起不丢失草稿。所有尺寸以可用视口为界，不强行把桌面宽度应用到手机。

## 2. 问题范围

| 范围 | 示例 | 处理方式 |
| --- | --- | --- |
| 项目功能与操作 | 如何添加自选、配置 MiniMax、生成早报、导入历史数据、使用回测 | 根据与运行版本匹配的项目说明回答 |
| 项目状态与排错 | 我的任务为什么失败、模型为何不可用、为什么没有候选 | 使用本人可访问的任务状态、错误码和研究结果解释 |
| 当前研究内容 | 这份报告为什么排除某证券、预算怎么算、回测中的回撤是什么意思 | 引用选定事实快照及项目中的计算口径 |
| 项目内对照 | 与上一版报告相比发生了什么、这两次回测有什么差异 | 比较本人明确选择且有权限访问的记录，标明各自时间和假设 |
| 范围不明确 | 只发送“帮我分析一下”，未指定对象 | 追问研究对象或提示选择项目内资料 |
| 项目范围之外 | 写旅游攻略、闲聊、处理其他项目的代码、分析系统没有资料的任意证券 | 简短说明可回答范围，并引导回 StockAI；不继续生成无关内容 |

股票、指标和费用等知识只有在解释 StockAI 功能或所选研究内容时才纳入回答。不能因为问题带有“StockAI”字样就放开范围。后续轮次与首次提问执行相同的范围检查。

范围控制需要服务端问题判定、受限资料检索和回答校验共同落实，不能只依赖前端提示或一句模型指令。要求忽略限制、改变角色，或藏在文档、历史消息中的指令，均不能扩大资料访问和回答范围。

## 3. 知识、上下文与引用

- 项目知识来自经选入的版本化使用指南、功能说明、错误码及帮助内容；区分已实现能力、待实现需求和待验证事项。不得把 PRD 中的规划写成已上线功能。
- 研究上下文仅来自服务端按当前用户权限读取的项目记录。前端提交的对象 ID、引用 ID、会话 ID 均需核验归属；不得信任客户端自行声明的用户身份。
- 用户可以选择关联的报告版本、证券、回测或模拟账户。发送前显示本轮将使用的资料范围，不默认附加全部个人研究空间。
- 涉及价格、候选、预算、费用、模拟持仓或回测结果的具体结论，应引用可打开的项目记录，包含对象或报告版本、数据时间和来源。引用 ID 与展示内容须经服务端核验，不采用模型随意生成的来源链接。
- 项目操作说明引用相应帮助文档及其版本。资料不足、已过期或无法核验时，明确说明缺口；不声称具有系统未接入的实时行情。
- 程序继续决定计算结果、候选和交易资格。对话只能解释或调用已定义的只读计算，不得用模型生成的数字替换已有结果，也不得改写历史报告。
- 首版使用项目知识和已保存资料，不接入任意网页搜索、文件上传或服务器目录扫描。对话不执行下单、修改设置、删除数据、运行代码或其他写入动作；可提供到相应功能页面的链接。

## 4. 模型与数据授权

- 默认使用本人的默认模型配置；允许在对话中明确选择本人其他有效配置。每轮提交时固定配置版本，切换模型仅影响之后的新请求，不自动切换其他服务重试。
- 用户主动提交的本轮问题和必要历史消息属于对话输入，应在入口说明将发送至所选模型服务。这不等同于授权系统自动读取或追加账户名、自由备注、登录身份和其他未授权数据。
- 模拟账户汇总和逐笔成交继续按所选模型配置分别授权，默认关闭；未获授权时提示开启对应授权或改问不涉及明细的问题。不得仅因用户提问就自动扩大授权。
- 每轮发送和重试前重新检查账号、凭据及授权。新模型配置不继承另一套配置的数据授权。
- 历史消息、引用和用于压缩长对话的摘要也受当前授权约束。关闭授权、删除关联资料或切换到权限较少的配置后，不得通过重发旧历史和摘要继续发送受限内容。
- 不自动读取或发送 API Key、密码、会话令牌、邮件凭据及服务器秘密配置；用户输入疑似凭据时提示移除，并避免将其写入普通日志。
- 用户只能访问自己的对话及关联资料；管理员后台不增加查看他人对话内容的入口，沿用现有服务器运维和加密备份的权限边界。

## 5. 对话与任务行为

- 保存个人会话、消息、关联资料版本、所用模型及调用状态，支持历史列表、新建和删除；未完成回答明确标为中断或失败，不展示为完整结果。
- 每次主动发送对应独立请求标识。重复点击、刷新或断线重连应复用已有请求状态，不重复消耗模型额度。主动重新生成需明确操作，并保留版本关系。
- 同一会话同时最多一个未结束回答，同标识不同内容应报冲突；每条问题上限 4,000 个 Unicode 码点，默认上下文优先指定事实和最近 10 轮，超出时按完整需求第 5 节处理，不静默裁剪当前问题。
- 对话与报告共用既定资源上限：每人最多一个运行任务、一个排队任务，全站最多两个模型执行槽；不能通过对话入口绕开限制。排队状态对用户可见。
- 支持经服务端校验的内容逐步展示和停止生成，不透传未核验的原始文本；不能安全增量校验时完整验证后展示。停止后取消未发送任务，并尽力中止在途请求；已发出的内容和供应商已计入的用量不能撤回，界面应准确显示状态。
- 断线或刷新按原请求及已确认片段序号恢复，不再调用供应商；未完成内容保留中断状态，不能在重连后自动变成新消息或完整答案。
- 模型不可用、Key 失效、限流或上下文超限时给出具体原因。对话失败沿用最多一次临时错误重试的边界；结果不确定的超时不自动重发。规则报告的回退机制继续适用于报告，对话失败不伪造回答。
- 上下文过长时使用经过授权检查的必要历史或摘要，并明确提示已省略早期内容；不得无提示截断用户当前问题或关键证据。
- 记录可取得的调用次数、用量、耗时和错误；供应商未返回的用量标为未知。后台不在用户没有主动发送时自动开启新对话或追加推理调用。
- 对话、连接测试、报告及其重试共享本人的日/月调用上限；范围判断或历史摘要若单独调用模型也计入。每次发送前原子检查和预留，超过上限时显示原因，不自动切换配置。具体计数、跨日和结果不确定的规则见研究工作台增强需求。
- 删除对话后，其在线消息、摘要及私有引用索引一并清理，不再参与检索和模型输入；在途结果不能写回。备份恢复先应用最新资源删除与账号注销状态，不能带回已删会话；对话正文不写入普通运行日志。

## 6. 验收标准

以下为待实现功能的计划验收条件，不计入现有版本的测试通过结论。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| CHAT-01 | 询问如何配置模型或生成早报 | 根据对应版本的项目说明回答，引用可打开的帮助资料 |
| CHAT-02 | 从本人报告页面询问为何排除某证券 | 使用选定报告版本的事实、排除原因及数据时间，不改写原档 |
| CHAT-03 | 询问旅游攻略或其他项目代码，或用“忽略限制”绕开范围 | 仅说明可回答范围，不生成无关答案；连续多轮和角色切换同样受限 |
| CHAT-04 | 项目问题缺少对象或所需资料 | 引导选择对象或明确资料缺口，不编造行情、研究记录或来源 |
| CHAT-05 | 用户 A 构造用户 B 的会话、消息、报告或引用 ID | 无法读取、追问、删除或引用 B 的数据；后台也无他人对话正文入口 |
| CHAT-06 | 未授权成交明细却询问逐笔成交 | 模型请求中不出现该明细，界面提示所需授权 |
| CHAT-07 | 已讨论成交后撤销授权，或切换到未授权配置再追问 | 新请求、历史和摘要均不再发送受限明细；历史引用不绕过当前权限 |
| CHAT-08 | 问题、引用文档或历史消息包含越权指令或索要凭据的内容 | 不扩大检索范围，不泄露秘密，不执行写入动作 |
| CHAT-09 | 报告已过期，或知识库同时包含规划和已实现功能 | 标明数据时间，区分计划与现状，不声称是实时数据或已上线能力 |
| CHAT-10 | 重复发送、断线刷新、连续点击重新连接 | 同一请求只执行一次；状态可恢复，不产生隐式重复调用 |
| CHAT-11 | 报告和对话同时排队，或中途更换默认模型、删除 Key、停用账号 | 共享并发限制；已提交配置固定，撤销与停用阻止未发送调用 |
| CHAT-12 | 停止生成、供应商超时、Key 无效或限流 | 状态准确、错误可见，遵守重试边界；不确定发送不自动重发 |
| CHAT-13 | 模型编造引用、数值与事实快照不符，或回答中混入无关内容 | 不作为有效完整回答发布，提示校验失败或资料不足 |
| CHAT-14 | 长对话、删除会话和账号注销 | 历史裁剪有提示，删除后在线上下文不可再用；注销后在途结果不得写回 |
| CHAT-15 | 选择两个报告版本比较，或对同事实快照切换模型解释 | 引用两侧资料、数据时间和程序计算差异；区分事实变化与措辞变化，不改写报告 |
| CHAT-16 | 追问为何排除证券或费用为何超预算 | 对照指定版本的排除记录及程序计算解释，不以模型生成数字替代已有结果 |
| CHAT-17 | 比较对象不存在、无权访问或缺少事实证据 | 提示选择有效资料或说明缺口，不拼接他人资料、不以最新行情填补旧事实 |
| CHAT-18 | 剩余一次日/月额度时对话与报告并发，或对话需额外摘要调用 | 所有模型请求分别预留并计数，最多一次实际发送；超限可见，不隐式更换配置或重发 |

## 7. 实施衔接

实现时复用现有身份隔离、个人模型配置、地址校验、凭据加密、任务队列和注销检查；增加适用于对话的消息存储、范围判定、知识检索、上下文授权及引用校验。现有报告的结构化输入和输出协议不能直接当作任意对话协议使用。

需补充对话页交互、服务端 API 与存储设计，以及跨用户访问、权限撤销后的历史重发、范围绕过、引用伪造、断线去重和报告/对话共享并发的专项验证。真实模型的相关性、引用质量和流式行为另行联调，不以受控替身测试代替。

输入预算、状态和资料契约按完整需求落实；新增 32 项 COMP-AC 验收中的对话、权限、迁移及整机目标同样适用。具体接口路径和存储表名可以按代码组织确定，不能变更项目范围、授权、调用计数及来源校验的产品要求。

双入口共用会话状态及请求恢复逻辑，避免悬浮与独立页各自实现一套生成流程。新增 8 项界面验收见独立登记；本次需求更新不作为界面改造或浏览器验证已经完成的结论。
