1. 产品背景与目标

用户现有自选股分布于普通 A 股、场内 ETF、贵金属股票，并关注国际黄金、白银行情。希望将原 Grok 研究提示词产品化，减少云模型额度消耗，实现每日早报、短线模拟候选、周度复盘与历史回测。

1.1 核心目标

Windows 桌面端和 Web 端共享同一业务后端、研究数据库、模型和权限体系。

定时采集可靠市场数据并产出可追溯报告；每日最多输出 3 只模拟研究候选。

严格校验每只证券模拟买入总成本（含预计买入费用）≤ ¥1,000。

将数据采集、确定性计算和 AI 文本生成分离，禁止模型凭空生成价格或交易状态。

所有交易均为研究或模拟；全部版本均不接入真实证券下单。

1.2 非目标

不构建高频交易、自动买卖或收益保证功能。

不以 AI 自然语言代替行情验证、费用计算、正式回测引擎。

不支持绕过市场准入限制或进行中国大陆受限虚拟货币交易。

5. 关键业务流程

5.1 每日研究流水线

任务触发 → 检查中国 A 股交易日历 → 获取市场数据和公告 → 校验质量/时间 → 核验证券交易资格 → 计算指标 → 预算与成本筛选 → 选出最多3只模拟候选 → 调用 Ollama 生成说明 → 事实一致性检查 → 存档与展示。

5.2 单笔预算硬性规则

模拟买入总成本 = 成交价 × 合法买入数量 + 预计买入费用；仅当总成本 ≤ ¥1,000 时才可作为可执行的模拟候选。普通主板 A 股通常按 100 股整数倍买入，具体规则、各 ETF 的单位与交易权限以交易所和产品规则核验为准。

未知佣金时应用明示的假设费率，并输出费用敏感性；不能将未知最低佣金写成确定值。超预算、交易状态未知、ST/退市/停牌的证券保留观察资格，但不得进入普通模拟买入名单。

5.3 候选评分与限制

前置门槛：交易状态核验通过、数据新鲜度符合要求、流动性达标、预算可执行。

评分维度：趋势、成交量、相对强弱、公告与基本面风险、成本、风险收益情景；主观得分不等于上涨概率。

候选数：0—3；无足够依据时必须输出“今日无合格模拟候选”。

每个候选必须给出报价时间、研究原因、反方观点、模拟数量、预计费用、失效条件及来源。

5.4 定时策略

任务 | 建议时间（Asia/Shanghai） | 产出

早报 | 每天 08:00 | 交易日标识、前收盘与最新贵金属行情、风险核验及候选

收盘更新 | A股交易日 16:00 | 收盘价格与当日模拟信号跟踪

周度复盘 | 周日 20:00 | 交易档案、策略表现、回测与下周关注

失败补偿 | 任务失败后按退避策略重试 | 重试日志、告警、避免重复报告

08:00 的 A 股部分应使用上一交易日已确认数据，不得将其标为当日实时交易价格。Windows 主机休眠或关机可能错过任务；需设置唤醒/补跑策略。

6. 数据与AI设计

6.1 数据适配层

初始采用 AKShare 及可使用的交易所/基金公司官方数据；采集器统一输出标准 Schema。

每条行情必须包含报价时间、采集时间、来源、币种、价格单位、复权口径及异常状态。

若网络中断、字段缺失、接口变更或行情过期，终止对应候选生成，记录原因。

财务公告与风险状态必须有可核实的权威来源；仅有历史截图无法证明当前上市状态。

6.2 模型职责边界

Ollama 模型：qwen3-14b-16k:latest；默认本地 HTTP API。Python 计算指标和数量，AI 只解读结构化事实、解释风险并写报告。报告生成后通过程序校验：候选数量、费用与预算、证券状态、价格来源和引用时间。

建议结构化输出 JSON：summary、market_context、candidates[]、excluded[]、risk_notes、sources[]、missing_data[]。失败时重试一次并退化为不含 AI 解释的规则型报告。

6.3 回测要求

使用 Backtrader 或等价 Python 框架；策略与数据版本化，严格处理 T+1、复权、停牌、涨跌停、费用、滑点、信号成交时点、幸存者偏差与未来函数。周度回测按需执行，不能以语言模型估算替代真实回测。

7.1 桌面体验

建议 Windows 桌面端采用 PySide6 + Qt WebEngine 嵌入同一套 Web UI；单实例启动后管理本地后端进程，桌面入口与托盘状态可选。避免桌面端与 Web 端分别实现业务逻辑。

7.2 Web体验

建议 Vue3 + TypeScript + ECharts；桌面与移动端自适应。默认仅监听 127.0.0.1，若开启局域网访问必须引入鉴权、会话保护和防火墙策略，避免直接公开 Ollama 端口。

9. 非功能需求

安全：本地 API 默认不监听公网；日志不记录凭据；如需移动端访问，必须显式启用身份验证。

可靠性：任务幂等；网络失败可重试；报告写入采用临时文件+原子替换；失败保留上次成功结果并标识过期。

可追溯性：行情与报告保留来源、抓取时间、策略版本、模型名称与参数摘要。

性能：单次日报在数据源可用的前提下，目标 10 分钟内完成；实际耗时应经本机基准测试确认。

可维护：行情提供方适配器化；前后端日志分层；配置与业务代码分离。

兼容：Windows 10/11 64 位；仅支持本机 Ollama；GPU 显存占用过高时提示并防止并行大模型任务。

备份：SQLite 定期备份；报告和配置可导出，不允许凭空恢复未持久化的历史内容。

13. 主要风险与待确认项

数据源可用性：免费财经接口可能限流、变更或中断；需准备官方核验和降级策略。

券商佣金：未知用户真实费率，必须提供可配置参数；默认值不得作为事实。

历史名单准确性：历史简称及退市状态可能变化，以最新官方证券信息为准。

回测质量：历史数据完整性、复权口径和幸存者偏差都会显著影响结论。

运行环境：系统睡眠、断网、Ollama模型未加载、GPU被游戏占用均可能导致任务失败。

初始总本金未知：只对每只1000元做仓位硬约束；整体账户风险和行业集中度需要总资金参数。

是否提供移动端局域网访问及实际消息通知渠道，纳入统一版本验收，但默认关闭外网访问，通知需先完成配置。
