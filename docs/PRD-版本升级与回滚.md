## 1. 产品目标与权限

提供版本检查、更新说明、下载验证、升级预检、备份迁移、安装切换、健康检查、失败恢复和历史记录。用户无需通过覆盖运行目录猜测升级步骤；管理员能清楚了解维护影响及数据是否可回退。

| 组件 | 操作入口与权限 | 升级边界 |
| --- | --- | --- |
| 桌面独立模式 | “设置 → 关于与升级”；本机工作区所有者确认 | 升级本机程序及本机 schema，保留工作区与未同步记录 |
| 桌面远程客户端 | 同一入口检查本机客户端，并展示远端兼容状态 | 更新本机不触发远程 Web/Hub 升级，也不修改远程数据 |
| Web 服务 | 管理员查看版本和升级计划；服务器运维执行受控 CLI/脚本 | 普通用户仅查看当前版本及维护通知，无代码安装权限 |
| 自建 Hub | 该服务管理员检查，运维独立升级 | 不强制同时替换桌面或 Web；先核对协议兼容关系 |

Web/Hub 可以使用预先配置的受限升级执行器承接后台发起操作；没有执行器时明确显示“待服务器执行”并提供对应计划，不能把下载成功显示为服务升级完成。浏览器请求不得直接运行任意脚本、镜像地址或系统命令。

## 2. 版本检查与更新通道

- 首次安装默认稳定通道；已有预览安装保留预览通道。用户可明确切换通道，预览版本不因字符串排序被误判为高于所有正式版，切换也不自动执行降级。
- 默认开启后台检查：联网启动时仅在从未检查或距最近自动检查已满 24 小时时检查，运行期间也最多每 24 小时自动检查一次；可关闭或手动立即检查。检查只发送组件、版本、通道、平台/架构及协议能力，不发送账号、研究内容、硬件唯一标识或模型凭据。
- 默认仅提示，不自动安装、重启或停服。自动下载可由本人/管理员开启，安装仍需确认具体目标版本；可稍后处理，不在有未保存编辑时直接中断用户。
- 页面显示当前及目标组件版本、发布时间、更新内容、包大小、依赖要求、维护影响、schema/同步协议变化和回退条件。多个独立服务分别显示，不能用本机版本冒充远端版本。
- 网络不可用、更新源限流或版本资料过期时显示检查失败及最近成功时间，不显示为“已经最新”；失败重试有退避，不影响现有研究使用。

## 3. 更新源、发布清单与包验证

- 更新源为项目配置的可信 HTTPS 发布源，可使用现有 GitHub Release 分发经验证的发行物；管理员可配置镜像，但不能因此绕过发布身份验证。普通用户不能把任意 URL 转为服务器代码执行入口。
- 每个发行目标提供经过签名的发布清单，至少包括组件、版本/通道、平台/架构、安装形态、包大小及哈希、下载地址或镜像摘要、最低来源版本、迁移路径、schema/API/同步协议支持范围、回退说明和发布时间。
- 客户端验证清单签名、有效期、可信密钥及目标匹配，再验证下载包的长度和 SHA-256。校验和用于内容完整性，不能单独代替发布者身份验证；可信根来自已验证的安装或运维配置，不能由同一未验证下载自行替换。
- 支持签名密钥的可验证轮换，拒绝失效、过期或被撤销信任的元数据。普通更新流程拒绝旧元数据回放和隐式降级，明确的回退操作另按第 8 节处理。安全目标参考 [TUF 规范](https://theupdateframework.github.io/specification/latest/)，具体库和签名部署在实现时确定。
- 包与当前组件/形态对应：EXE 更新不能误装源码包，Windows x64 不能误装 Linux 包，本地版不能被公网包覆盖。用户已有数据库和密钥不应出现在发行包中。
- 支持断点续传与取消下载；继续传输前核对相同目标与内容标识，不拼接不同版本。完成验证前不运行下载内容，不写入当前活动安装。
- 支持导入离线签名升级包，执行相同的身份、有效期、兼容和迁移检查。无法验证时保留旧版本并说明原因，不提供默认“忽略校验继续”。

## 4. 升级预检与计划

升级前生成计划，列出目标组件、来源与目标版本、需要暂停的服务、迁移步骤、备份位置、预计空间、兼容要求和可回退状态；确认的是这份具体计划。

预检必须检查：安装目录与工作区识别正确、读写及执行权限、程序/运行时要求、包可信、当前 schema 与迁移路径、可用空间、恢复材料、后台任务、未保存编辑、未同步记录，以及当前是否已有升级/恢复流程。空间估算包含下载、暂存、备份及迁移临时开销，不仅计算压缩包大小。

同一组件/工作区只允许一个升级事务，重复点击返回已有进度。不同工作区独立处理；不能因一份 EXE 被复制到新目录就迁移错误工作区。缺权限或预检失败时清楚说明处理方式，原服务与数据保持可用。

不可逆或无法无损回退的迁移需要在确认前显著说明。无法找到安全兼容路径时阻止自动执行，不能假设任意旧版本都能直接跨越到最新版。

## 5. 桌面升级

1. 下载或导入并验证适用的升级包，展示更新内容与影响，提示处理未保存内容。
2. 进入升级状态，停止新的本机研究写入、同步上传/应用、自动任务和通知发送；等待在途操作结束，保存未决模型/邮件状态。
3. 创建可验证的恢复点，退出占用当前程序的本机实例，由受控更新进程在暂存区域准备新版本，不覆盖运行中的可执行文件。
4. 迁移并校验本机数据，切换活动程序，启动一次新版本并进行健康检查；验证通过后再开放写入和调度。
5. 失败按第 8 节恢复并展示原因、当前实际版本及数据状态；成功显示版本与升级记录。

桌面 EXE 仍保持程序、解包缓存和持久工作区分离。现有 `%LOCALAPPDATA%\StockAI\workspace` 中的 `data`、`control`、`secrets` 及用户指定工作区不因替换 EXE 被重置。源码形态提供同等预检与受控升级步骤，不强制转成 EXE。

远程客户端模式仅暂停和更新本机客户端，保留站点绑定和安全存储；远程研究任务由服务器管理，不能将本机退出当作远程任务取消。客户端过旧时提示兼容要求，不能通过忽略协议版本写入远程服务。

## 6. Web / Hub 升级及兼容顺序

- 支持检查、预演、准备、执行、查询状态及受控回退的 CLI/脚本能力，记录实际运行版本。实际命令、路径及权限在交付文档中给出，不把尚未存在的命令作为已可用入口。
- 在维护窗口暂停新写入、任务领取、模型发送、通知投递及同步应用，等待或明确终止在途任务；已发送结果不明的请求保留不确定状态，升级后不自动重发。
- 预先准备经验证的新镜像或代码包，再创建检查点、迁移和切换；以镜像摘要或已验证构建标识锁定目标，不以可漂移的 `latest` 表示已确认版本。
- 镜像拉取与启动切换分别登记；拉取成功不代表服务已更新。[Docker Compose pull 文档](https://docs.docker.com/reference/cli/docker/compose/pull/)
- Web 前端、API、静态资源和数据库采用同一发布兼容集合。切换后旧浏览器缓存应提示刷新或重新加载，不能混用新页面与不兼容旧 API。
- 基于发布清单计算 Hub、Web、桌面的升级顺序：目标支持旧端时可分批升级；没有兼容中间状态时明确统一维护窗口。不能固定假设永远先升级某个组件或永远兼容前一版。
- 暂时未升级的端可保留本地可读历史；遇不支持的同步协议/schema 时停止相关写入并提示升级，不丢弃离线变更，也不强行上传旧格式。
- 不自动升级第三方 WebDAV/NAS、操作系统、模型权重或模型服务。WebDAV 适配及同步格式随对应 StockAI 组件发布；现有地址、模型选择和用户设置应保留。

## 7. 数据迁移与健康检查

- 升级检查点覆盖实际业务库、归档及引用文件、配置、同步待发记录、设备和写入代次，以及最新删除/用量控制状态。需要的密钥版本和备份解密材料独立受控保管，不放入发行物或普通同步包。
- 使用一致快照和清单验证可恢复性，不复制使用中的数据库文件并假定其完整。备份沿用当前部署模式的加密、权限和保留规则；备份或关键恢复材料缺失时不进入不可恢复迁移。
- 迁移按来源 schema 顺序执行、可重复检测，记录开始/完成和版本；中断后可安全继续或恢复。旧程序拒绝写入不兼容的新 schema，不能仅回退版本字符串。
- 保留个人归属、历史判断、报告/实验快照、费用、模型配置与授权、关闭的自动化开关及同步关系。新增字段采用有版本的默认值，未知历史不补成虚构事实。
- 健康检查包含版本、API/前端匹配、数据库完整性及关联、关键记录数量、归档哈希、控制状态、队列和同步能力检查。默认使用本地/只读检查，不发送真实 AI 请求、模拟交易或邮件作为自动验活。
- 所有检查通过后才退出维护模式并恢复允许的任务；恢复按现有幂等、仅当天计划及不明请求不重发规则执行，不能把历史任务、订单或通知重新跑一遍。

## 8. 失败与回滚

| 时点 | 必须采取的处理 |
| --- | --- |
| 检查、下载、验签或预检失败 | 原版本继续运行，记录失败原因；未验证内容不执行 |
| 备份、迁移或切换失败，尚未重新开放写入 | 自动恢复受控的旧代码与一致数据检查点，核对最新控制状态；恢复失败则保持维护模式 |
| 新版本启动或健康检查失败，尚未开放写入 | 按可回退计划恢复；不能将进程启动成功当作健康通过 |
| 已开放新版本且已有新数据 | 先停写并创建当前恢复点；只按兼容的逆迁移/保留新数据方案回退，不直接覆盖为升级前备份 |
| 迁移不可逆或缺少有效恢复点 | 明确“无法自动无损回退”，保留当前数据及维护状态，提供修复版本或受控恢复引导 |

自动回滚不能回退最新删除墓碑、账号注销、已发送模型用量及通知未决事实；需要与其独立控制记录重新核对。同步未决记录、账本分支和已确认调用 ID 不因回滚而丢失或复活。

回滚属于明确的受控操作，不由更新源返回一个较低版本自动触发。完成后显示真实版本、恢复点、资料完整性和是否仍有阻断；不能在恢复未完成时显示成功。

## 9. 状态、历史与清理

页面区分检查中、有更新、下载中、已验证、预检阻断、等待确认、备份中、迁移中、切换中、健康检查、升级成功、回滚中、已回滚和需人工处理。显示当前步骤、可取消阶段、错误原因及脱敏诊断；迁移/切换中不提供会留下半套安装的直接取消。

下载可暂停/取消，已开始迁移后的停止请求只能在安全边界受理。断网、断电和重启从持久升级事务恢复，未完成时先进入恢复流程，不启动两份后台同时读写。

记录升级事务 ID、组件、操作者、来源/目标版本、已验证包摘要、schema/协议变化、检查点引用、开始结束、迁移结果和回滚原因。不记录研究正文、密码、Key 或访问令牌；向外导出诊断前脱敏。

至少保留最近一个可用旧代码包及对应恢复点状态，数据检查点按既有 30 天备份规则清理。仅清理本应用确定归属的过期下载、暂存和旧代码缓存，不删除工作区、密钥、控制状态、未同步记录或用户自选目录。恢复点过期后页面同步标明回退能力变化。

## 10. 计划验收标准

以下 32 项均待执行，登记在 [升级验收清单](验收清单-版本升级与回滚.md)，与原有研究和同步验收分开维护。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| UPG-AC-01 | 稳定/预览、版本比较和通道切换 | 版本判断正确，已有预览通道不被静默更改，不隐式降级 |
| UPG-AC-02 | 普通用户、管理员、本机所有者与远程客户端 | 升级权限和组件边界正确，无任意服务器命令或代码安装入口 |
| UPG-AC-03 | 启动检查、24 小时周期、断网及更新源限流 | 不频繁重试，不把失败显示为最新；只发送必要软件元数据 |
| UPG-AC-04 | 桌面在线升级正常路径 | 展示计划并经确认后安装，新版本健康通过再开放使用 |
| UPG-AC-05 | EXE 位置改变、用户自定义工作区与源码形态 | 正确定位工作区，资料/控制/密钥不重置，不误转安装形态 |
| UPG-AC-06 | 桌面远程客户端升级 | 仅更换本机客户端，远程站点、任务和数据不被本机退出或升级修改 |
| UPG-AC-07 | Web/Hub 运维升级及无执行器环境 | 受控执行有记录；只准备计划时显示待执行，不冒充升级完成 |
| UPG-AC-08 | Hub/Web/桌面支持范围不同 | 按兼容矩阵分批或停服升级，不兼容端停止写入且保留离线变更 |
| UPG-AC-09 | 新前端与旧浏览器缓存/旧 API 混用 | 提示刷新或阻止不兼容调用，组件版本组合一致 |
| UPG-AC-10 | 错平台、架构、组件、形态或不支持的来源版本 | 预检拒绝，不覆盖当前安装或数据库 |
| UPG-AC-11 | 包被篡改、签名无效或仅有可修改的校验和 | 未通过可信身份和完整性检查的包不执行 |
| UPG-AC-12 | 元数据过期、密钥轮换与旧元数据回放 | 按信任链检查，旧内容不触发隐式降级，失败原因可见 |
| UPG-AC-13 | 下载中断、续传与不同版本片段 | 只续传同一目标，完整校验前不运行，不拼接不同内容 |
| UPG-AC-14 | 自定义源、恶意重定向或包内异常路径 | 不绕过可信来源和目标目录边界，不写入任意系统位置 |
| UPG-AC-15 | 离线导入有效/无效签名包 | 验证规则与在线一致，无效包不安装，不暗中联网调用模型 |
| UPG-AC-16 | 磁盘不足、权限不足、缺依赖与重复升级 | 预检明确阻断，单工作区单事务，旧版本保持可用 |
| UPG-AC-17 | 备份缺失、解密材料不可用或清单损坏 | 阻止不可恢复迁移，恢复点确实可验证 |
| UPG-AC-18 | 运行中模型、通知、同步及未保存编辑 | 暂停新写入，处理在途与未决状态，不强制丢弃编辑或重复执行 |
| UPG-AC-19 | 旧 schema、重复迁移和迁移中断 | 迁移有序且幂等，旧代码不能写入不兼容新 schema |
| UPG-AC-20 | 解包/切换时断电或进程崩溃 | 重启进入可恢复事务，不启动半套安装或两份业务后台 |
| UPG-AC-21 | 新版本健康检查成功/失败 | 检查版本、完整性及关键资料，默认不发真实 AI、订单或邮件 |
| UPG-AC-22 | 开放写入前失败自动回滚 | 旧程序和一致数据恢复，最新控制状态不倒退，结果准确显示 |
| UPG-AC-23 | 新版已产生数据后请求回退 | 先保存当前状态，不能直接用旧备份覆盖新记录 |
| UPG-AC-24 | 不可逆迁移或无有效恢复点 | 升级前明确确认影响，失败不虚报自动无损回滚 |
| UPG-AC-25 | 升级前存在待同步、冲突及账本分支 | 记录与关联保留，升级后按版本继续处理，不丢失唯一副本 |
