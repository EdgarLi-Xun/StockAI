## 1. 实现基线

沿用 Python、FastAPI、Vue 和 SQLite；新增独立的公网应用入口，使用显式用户上下文和持久任务状态。先完成账号和数据归属，再连接模型、调度及运维功能。

| 部分 | 实施选择 | 原因与边界 |
| --- | --- | --- |
| Web 后端 | 新增公网入口 `backend/public_app.py`，复用可独立验证的研究计算 | 公网入口没有本机自动管理员身份；现有 Windows 入口的同步改造另行安排 |
| 数据库 | SQLite、本机持久卷、短事务、WAL | 延续现有 SQL 与备份能力；SQLite 同时只有一个写者，因此网络请求、哈希计算和长计算不放在写事务内 |
| 服务进程 | 一个 API 进程、一个调度循环、两个报告执行槽 | 与首发单机目标匹配；运行配置明确限制为一个 Uvicorn worker |
| 任务状态 | SQLite 队列表、租约、心跳和每次外部调用记录 | 进程重启后可以判断排队、中断和请求结果不确定，不依赖内存队列恢复任务 |
| 账号会话 | 服务端持久会话，浏览器使用安全 Cookie | 用户、停用、重置密码和注销均可即时撤销会话 |
| 凭据保护 | `cryptography` 的 AES-GCM，独立密钥文件 | 凭据密文与用户、配置和用途绑定，应用读取接口不返回完整 Key |
| 备份加密 | 调用标准 `age` 工具，使用运维接收公钥 | 使用现成文件加密格式；备份解密身份由运维单独保管 |
| 部署 | Docker Compose：应用与 Caddy；SQLite 数据使用本地卷 | Caddy 提供 HTTPS 入口；数据库、报告和备份目录不直接作为静态站点公开 |

SQLite 的 WAL 仍存在单写者限制，以上是针对已确认首发规模的工程选择，并非已验证的容量结论。[SQLite WAL 文档](https://sqlite.org/wal.html)

构建阶段核对实际 `sqlite3.sqlite_version`。多连接 WAL 运行时采用包含 WAL-reset 修复的版本，例如 3.51.3 及之后版本，或官方列出的修复回移版本；不能只凭 Python 版本判断。具体版本在基础镜像验证后锁定。[SQLite 修复说明](https://sqlite.org/wal.html#walreset)

## 2. 模块边界

以下目录和名称为实现定位，开发时可按实际代码组织调整，不改变权限和数据边界。

| 范围 | 现有主要位置 | 计划职责 |
| --- | --- | --- |
| 公网入口 | `backend/app.py`、`backend/security.py` | 新增公网 app、认证依赖及管理员依赖，拒绝隐式本机身份 |
| 用户与权限 | 当前仅共享角色密码 | 新增用户、会话、邀请码、邮箱令牌、再次验证与角色管理 |
| 数据归属 | `backend/db.py`、`backend/instruments.py` | 迁移脚本与带用户范围的 repository；拆分证券资料和个人自选 |
| 研究与模拟 | `backend/research.py`、`backend/simulation.py`、`backend/backtest.py` | 显式传入用户及个人参数；沿用已有确定性规则、来源和回测验证 |
| 共享采集 | `backend/collectors.py`、`backend/context.py` | 对活跃自选证券去重采集，缓存公开资料；个人报告仅使用自己的自选和研究参数 |
| 模型接入 | `backend/ai.py` | 分离模型配置、凭据、输入投影、适配器及错误分类 |
| 任务与计划 | `backend/jobs.py` | 持久领取、配额、调度、重试、撤销检查及报告版本 |
| 邮件 | `backend/jobs.py` 中的站点通知 | 独立事务邮件与 outbox，支持验证和密码重置 |
| 数据维护 | `backend/maintenance.py` | 一致性快照、加密备份、保留清理、独立注销记录及离线恢复 |
| 前端 | `frontend/src/App.vue`、`frontend/src/api.ts` | 账号页面、个人模型配置、任务状态、报告版本、管理员页面；按页面拆分组件 |
| Linux 交付 | 当前安装与启动脚本主要面向 Windows | `deploy/cloud/` 配置、构建文件、初始化与恢复 CLI、部署说明 |

公网私有业务服务必须显式接收用户身份，不能用 `None`、空字符串或管理员角色替代用户过滤。旧的全局查询函数不能未经改造直接挂到公网路由。

## 3. 数据结构与约束

### 3.1 新增基础结构

| 计划结构 | 主要内容和约束 |
| --- | --- |
| `users` | 不复用的用户 UUID、唯一登录邮箱、密码哈希、验证时间、角色与账号状态 |
| `sessions` | 会话令牌哈希、用户、过期及撤销状态；不保存原始浏览器令牌 |
| `invitations` | 邀请码哈希、生成者、7 天有效期、撤销及单次核销记录 |
| `auth_tokens` | 验证或重置用途、令牌哈希、过期及单次消费时间 |
| `mail_outbox` | 事务邮件发送状态；必要链接内容短时加密，发送后移除敏感载荷 |
| `user_settings` | 个人预算、费率、筛选偏好、报告计划和自动 AI 开关 |
| `user_watchlist` | 用户与共享证券关系；分组、置顶等属性随用户保存 |
| `model_profiles` | 用户、服务类型、地区、模型、配置版本及两项详细数据授权 |
| `model_credentials` | 用户与配置归属、密钥版本、随机 nonce、密文、撤销状态 |
| `model_calls` | 用户、任务、配置版本、尝试次数、请求状态、供应商请求标识和可用的用量；不存完整提示词或 Key |
| `report_series` | 同一用户、报告类型和目标日期的系列标识，与报告版本分开 |
| `admin_actions` | 停用、邀请码、备份导出等操作的必要审计元数据，不记录密码、Key 或私人研究正文 |

### 3.2 改造现有研究结构

- 共享证券、行情、日历、公开研究资料与风险证据保留共享归属。
- 共享采集从活跃用户自选的去重证券集合构建目标，个人报告的筛选仍按本人范围进行；公共接口不返回他人的自选关系。
- 报告、回测、模拟账户、个人任务和通知增加不可为空的用户归属。
- 候选、订单、持仓、账本等子记录通过受约束的父记录归属；若同时保存用户字段，使用复合约束保证与父记录一致。
- 报告系列按 `(user_id, kind, target_date)` 唯一，归档版本按系列和版本号唯一；补充 AI 新建版本。
- 订单幂等键改为用户范围，不能因另一人使用同样的客户端键而读到对方订单。
- 私有列表与详情查询都携带所有者条件；查询不存在或不属于自己的资源使用一致的未找到结果。
- 所有个人下载先查询所有者，再定位受控目录中的文件；禁止通过拼接路径绕过权限。

### 3.3 注销记录独立存储

在独立持久目录维护注销记录库，只保存用户 UUID、注销序号、站点标识和处理状态等恢复所需元数据，不保存研究正文。正常整站恢复不会覆盖该目录。

注销先持久记录，再撤销会话、Key 和任务并清理主库、报告文件。中途崩溃时，启动恢复流程根据该记录继续清理，并在对外服务前拒绝已注销身份和相关写回。

这个顺序不依赖两个 SQLite 文件之间的跨库原子事务；失败后通过记录重放恢复。灾备必须独立保管最新注销记录，不能用所选旧备份中的记录冒充当前记录。无法取得可信的最新状态时，恢复流程拒绝上线。

## 4. 迁移方案

1. 保留源码和数据基线；从现有数据建立可恢复快照，按 PRD 的加密和保留规则管理。
2. 由运维初始化明确的管理员身份；不将现有共享角色密码直接转换为个人登录身份。
3. 在新的公网数据目录中迁移副本，保留现有本机数据源作为迁移输入。
4. 从 `instruments.watched/group_name/pinned` 生成管理员的个人自选关系，证券本身仍共享。
5. 将现有私人报告、回测、模拟账户及其关联数据归初始化管理员；拆开个人设置和站点设置。
6. 给历史报告建立系列及首个版本，保存原事实、日期、来源和文件内容；不重新调用模型改写历史。
7. 迁移历史任务记录及其归属；旧的未完成任务保留为待核查状态，不因迁移自动重发模型请求。新系统按当天规则和个人开关生成后续计划。
8. 校验前后数量、主外键、文件校验和、个人关联及新用户空白空间；演练回滚。

迁移按版本记录并可重复检测完成状态。任一归属或文件校验失败则不切换公网服务，修复副本后重试；不会一边迁移一边开放注册。

## 5. 登录、权限与前端入口

- 公网账号依次处于待验证、可用、停用状态；注销通过独立记录和清理流程处理。
- 邀请码采用单次原子核销，重复注册和验证重发不能生成多个账号；邮箱未验证时仅开放验证、重发和退出等必要流程。
- 新密码采用 `argon2-cffi` 的 Argon2id 哈希，存储算法与成本参数，支持登录时检查是否需要重哈希；在目标容器中验证内存成本和登录并发。[官方密码哈希说明](https://argon2-cffi.readthedocs.io/en/stable/howto.html)
- 会话使用随机令牌，数据库只存哈希；Cookie 设置 `HttpOnly`、`Secure` 和 `SameSite`，写操作核验同源及 CSRF。
- 初版会话沿用现有 8 小时上限；密码重置撤销旧会话，停用和注销立即撤销；令牌时效作为配置明确写入实现。
- 登录、邀请核验、验证码重发和密码重置均限速；邮箱发送结果不能泄露账号是否存在。
- 邮件链接从固定的公开站点 URL 构造，不使用请求中的任意 Host。邮件令牌单次使用，重发与消费状态一致。
- 管理员导出前再次验证当前密码，签发短时、单次且绑定会话与导出用途的凭证。
- 管理员路由仅操作账号、共享资料和运维；私有路由仍按其本人用户范围查询。

计划接口按能力分组：

| 分组 | 计划入口 |
| --- | --- |
| 认证 | `/api/auth/register`、`login`、`logout`、`me`、`verify-email`、`resend-verification`、`forgot-password`、`reset-password`、`reauth` |
| 个人 | `/api/me/settings`、`watchlist`、`model-profiles`、`reports`、`jobs`、`simulation`、`backtests`、`notifications` |
| 注销 | `/api/me/account` 的确认注销操作 |
| 站点管理 | `/api/admin/users`、`invitations`、共享资料维护及 `backups` |

前端移除公网模式下的角色密码登录和本机会话获取；增加验证结果、重置密码、空白空间、个人模型状态和排队状态页面。前端隐藏入口不替代后端授权。

## 6. 模型与数据授权

### 6.1 调用路径

`个人任务 → 固定配置版本 → 核验账号/凭据/授权 → 构建获准输入 → 供应商适配器 → 既有结构与事实校验 → 报告新版本或规则报告`

- 新增 MiniMax 国内、国际预设和通用 OpenAI 兼容适配器；保留独立 Ollama 适配器。
- MiniMax 使用订阅 Key 对应的官方入口，实施时核对实际可用模型和结构化文本能力，不照搬 Ollama 的请求参数。
- Ollama 地址仅由站点管理员配置，GPU 检查和本地模型互斥只作用于 Ollama。
- 模型健康与额度查询不自动生成研究报告；确需产生模型调用的验证操作应由用户明确触发并可识别其额度消耗。
- 默认输入只包含获准的自选、候选、来源及研究摘要；模拟汇总、逐笔成交按该配置的独立开关加入。账户名、自由备注、登录信息永不放进提示词。
- 沿用候选、来源、数字事实和收益保证表述等输出约束；校验失败进入规则报告，不发布未经校验的解释。
- 补充 AI 引用原报告事实并构建当前获准输入，创建新的归档版本；不修改原报告或重新采集成另一份事实后伪称原档补充。

### 6.2 凭据和出站访问

- AES-GCM 每次写入使用新的随机 nonce，认证附加数据绑定站点、用户、配置、密钥版本和用途。密钥文件与数据库及普通配置导出分开，支持显式轮换。[认证加密文档](https://cryptography.io/en/stable/hazmat/primitives/aead/)
- 任务保存配置版本和凭据引用，不保存可继续使用的旧 Key 明文；删除或轮换凭据后，旧引用不能被重试绕过。
- 自定义地址只允许公网 HTTPS，拒绝内嵌凭据、携带 Key 的 URL、服务器回环、私网、链路本地和元数据地址。
- 校验全部 IPv4/IPv6 解析结果，实际连接与已校验地址绑定，同时按原域名验证 TLS；关闭自动跳转和环境代理，避免校验后重新解析绕过。
- 服务器 Ollama 使用单独的可信站点路径，不能通过个人自定义配置取得同等访问权限。[OWASP 出站请求防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)
- 所有接口和日志只返回稳定错误分类及脱敏原因，不记录 Authorization、原始请求体、完整提示词或供应商原样错误正文。

## 7. 持久任务与报告归档

### 7.1 状态和并发

- 任务状态为排队、运行、完成、取消、失败或中断待核查；AI 回退以报告元数据记录，不等于整个任务失败。
- 领取任务、检查每人 1 运行加 1 排队及全站 2 运行、更新租约在短事务内完成；两个执行器不能重复领取同一任务。
- 长采集与模型请求不持有全局维护锁或写事务；报告发布与备份快照只使用必要的短临界区。
- 队列按用户公平领取，站点采集和运维另有调度范围；共享数据的刷新合并，避免两个个人报告各自重复刷新整个市场。
- 记录每次模型请求的准备、已发、收到结果或结果不确定状态；租约过期后，已发但未确认的请求不能自动重发。
- 进程重启先恢复未发排队任务；过期日期的任务不自动补造历史报告。明确可重试的临时错误最多重试一次。
- 停用、删除 Key、撤销数据授权时取消相关未发调用；发起每次重试前再次检查，注销后写入必须由同一事务中的账号状态条件阻止。

### 7.2 报告发布

1. 按个人范围构建并验证事实快照，记录所用配置版本和实际来源。
2. 调用并验证 AI；异常时构建带原因的规则报告。
3. 在受控目录写入临时文件并同步，提交前再次确认用户未注销。
4. 原子发布文件和归档元数据；失败或崩溃时通过发布状态清理孤立临时文件，不能留下公开可访问的半成品。
5. 归档记录保存模型服务、实际模型、配置版本、AI 状态和可获得的用量；默认配置变化不改写已存报告。

补充 AI 与普通生成均受每人排队及全站并发限制。定时任务遵守 PRD 的上海时区、个人默认关闭、三个计划和仅当天补跑规则。

## 8. 注销、备份和恢复

### 8.1 注销和清理

先写入独立注销记录，再撤销会话和凭据、取消队列，按依赖顺序清理候选、报告、模拟交易、回测、个人设置及文件。共享证券与公开行情不随个人注销删除。

在途请求结束后，条件写入检查阻止数据回生；文件清理可重试且启动时继续完成。技术验收分别检查 API 不可访问和在线副本已清理，不把设置账号状态当作完成全部数据清理。

### 8.2 每日备份

使用 SQLite 在线备份接口取得主库快照，并从该快照的清单复制不可变报告文件；快照建立与注销文件删除协调，复制期间对清单文件短时保留，完成后恢复清理。正常运行的备份不直接复制正在写入的主库及 WAL 文件。[SQLite 备份接口](https://sqlite.org/backup.html)

生成带版本、站点、时间、记录数量和校验和的归档，用 `age` 加密后才进入可下载目录；备份标识和密文摘要另作受控登记，恢复时核验来源。密钥恢复所需材料单独保管；临时明文目录权限受限，成功、失败及启动清理均覆盖它。[age 官方说明](https://github.com/FiloSottile/age)

每天清理系统管理范围内超过 30 天的副本；导出依赖管理员再次验证，导出副本按 PRD 由管理员管理保留期限。

### 8.3 恢复步骤

1. 进入维护模式，停止新任务，等待在途请求结束或记录结果不确定状态；数据库写入和调度停止。
2. 由服务器运维在本地 CLI 提供解密身份，核对受控登记的备份标识与密文摘要，在临时目录解密并校验清单、文件路径、数据库完整性和站点标识。
3. 读取独立保存的最新注销记录；缺少可信当前记录时中止，不从所选旧备份覆盖它。
4. 在恢复副本中清除已注销用户及其全部相关记录和文件，检查外键和所有者关联。
5. 清空恢复副本中的旧会话、邮件待发令牌、再次验证凭证；旧运行模型请求标记为不自动重发。恢复后的个人自动 AI 先关闭，模型配置标记待本人重新连接，防止从旧备份重新使用已删除的 Key 或消耗额度。
6. 保留当前状态的加密恢复点，替换经过校验的数据和报告目录，再执行权限、账号和模型凭据可用性检查。
7. 检查通过后解除维护模式；失败时保留当前在线状态或回到恢复点，并继续应用最新注销记录。

恢复功能以维护 CLI 和运维步骤交付，公网管理页面仅承担备份管理和受控导出，避免在普通 Web 请求中直接替换运行库。密钥轮换后应保留恢复仍在保留期内备份所需的密钥材料，并在恢复后重新保护当前有效凭据。

- 用并发领取和故障注入验证单次核销、并发上限、重复点击、进程重启、请求发出后断电及注销写回竞争。

- 每个阶段运行其相关测试，改动确定性研究、模拟或回测模块时运行原有回归；前端执行类型检查和生产构建。

- 目标环境通过应用配置真实 MiniMax 国内/国际订阅测试配置、Ollama 及代表性兼容接口，分别记录已验证能力。模拟 HTTP 通过不能代替真实订阅接口联调。
- 实际 SMTP、域名/TLS、Linux 重启恢复和备份解密演练在部署验收阶段完成；未完成项明确列入新版本验收记录。

## 11. 部署准备项

- Linux 主机与持久本地存储、公开域名及可用的 HTTPS 入口；Caddy 的证书自动化按其部署条件配置。[Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)
- 发件 SMTP、固定公开站点 URL、初始化管理员邮箱。
- 模型凭据加密密钥文件、备份接收公钥、运维解密身份和独立注销记录目录；配置示例只写占位符。
- MiniMax 及其他服务的真实 Key 由用户在个人模型配置中录入，联调结果另行记录。
- 应用和数据库入口留在受控网络，公网只暴露站点入口；可信代理范围、Host、请求体和超时在部署配置中明确。

原方案编制时仅完成需求确认和实施方案记录；后续公网基线的实际实现与验证情况见验收记录。以下新增需求目前完成范围定义和实施衔接，尚未实现或验收。
